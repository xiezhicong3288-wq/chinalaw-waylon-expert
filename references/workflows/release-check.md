# 发布与安装核对

先读 [公开边界](publication-privacy.md)。只发布经过核验的通用成果；公开首页仅保留能力、安装、使用及必要边界。

1. 在隔离候选中编辑，保存安装目录逐文件基线和私人回滚包；读取远端主分支及待处理 PR 的真实状态。安装、候选、PR、主分支是四种状态，分别记录，不相互代替。
2. `release-files.json` 是逐文件发布白名单。新增文件须人工审阅后明确加入；不能扫描目录后无条件刷新白名单。`release_guard.py --source <实际候选目录>` 检查路径一致性、链接、文本与常见敏感模式。再对实际发布目录运行同一命令。工具通过不等于语义隐私审查通过。
3. 运行相关回归与独立合成行为检查，人工审查新增文本、文件名、组合事实、第三方权利及误导性描述。原始材料和评估答复只留私人目录。来源结构、快照哈希、在线可达性、效力及个案适用分别记录；未测项不补写通过。
4. 检查实际 Git 暂存差异与提交树，确认提交作者及提交者使用获准公开的身份和邮箱，并审查分支、PR、Issue、Release 文案。尚未创建的外部对象记为未审，不用目录扫描替代。首次提交前也检查当前 Git 身份，避免先提交再发现隐私。
5. 向用户展示最终 README 全文、英文元数据及中文展示实现，按适用发布约定取得该版本确认。确认后内容再变更须重新展示；私人报告不作公开附件。
6. ZIP 仅收录白名单，逐文件比对名称与内容哈希，检查中文路径元数据并解压核验；先写临时包，通过后原子替换目标包。发布前复核最终 ZIP 与获准候选一致，不能仅看文件名数量。`package_skill.py --output <Skill外的包路径>` 仅生成本地包，不执行上传。
7. 安装前将当前目录与基线再比对；有并发修改则保留双方版本。写入后逐文件比对候选。`release_state.py --candidate <候选> --installed <安装> --pr-tree <已读取PR树> --main-tree <已读取主分支树> --output <私人状态报告>` 比较内容，缺少的远端树不得宣称一致。
8. 获准公开发布后，按仓库检查与分支保护完成 PR 流程，回读远端主分支并核验最终内容。不能用推送成功代替合并成功；历史、PR、归档和缓存残留分别报告，未经授权不重写历史。

正则无法识别全部私人过程或真实案件的组合事实。白名单也只能限制文件集合；对已列入文件新增的敏感内容仍须审阅。检查失败时保留本地候选，禁止以“平台限制”为理由放行个人邮箱或凭证。
